- **已实现证据**：服务端提供 session 鉴权的 `PATCH/DELETE /api/photos/:id`；迁移 `20261028001700_photo_owner_privacy_api.sql` 提供 owner-only 更新/软撤回函数与权限收口；详情页仅向作者显示编辑/撤回，编辑页只提交白名单字段并在撤回后清理相关缓存。
- **本轮验证**：编辑表单 3 个单元测试、服务端 patch/许可/边界测试和前后端完整质量门禁通过。
- **本轮真实数据库与 HTTP 验证**：`scripts/apply-and-test-photo-owner.ps1` 在隔离临时库完整应用迁移，先通过 owner-only SQL 断言，再以 `app_user` 启动真实 Fastify 注入旅程，验证 Cookie 会话、Origin/CSRF、作者编辑、非法/不可变字段 400、非作者非枚举 404、软撤回幂等、匿名/非作者 404 与作者审计可见；4/4 集成通过，临时库随后强制删除。
- **本轮修复**：新增 `20261028001900_app_user_read_privileges.sql`，补齐 profiles/categories/articles/comments/rankings 等 RLS 表的基础 SELECT 权限；此前 fresh database 虽有 RLS 策略，但 app_user 因缺表级权限在会话 profile 查询阶段直接 42501。
- **本轮浏览器验证**：新增同一 SPA 会话的 mock 撤回可见性回归；另新增隔离的 API 模式 Playwright 配置与临时库 harness，以真实 PostgreSQL、Fastify、Cookie/Origin/CSRF 和生产前端构建验证作者编辑持久化、非作者 UI/直达编辑隔离、作者撤回及匿名直达不可见。harness 强制 `STORAGE_CLEANUP_ENABLED=false`，仅使用虚拟对象 key，避免与图片清理实现并发冲突。
- **图片生命周期实现**：新增 `photo_storage_cleanup_jobs` 可靠队列；`api_remove_photo` 在同一数据库事务内软撤回并幂等入队，绝不等待对象存储。任务默认在撤回 30 天后可领取；服务端 worker 使用 `FOR UPDATE SKIP LOCKED`、短租约、对象删除幂等、指数退避与租约令牌完成异步清理，进程崩溃后可重试。
- **剩余验收**：0020 迁移的真实 PostgreSQL 并发/回滚验证，以及生产对象存储（OSS/S3）适配器与缓存/CDN 失效仍需单独落地。
