# 内置主体重设计方案（背景系统 · 主体目录替换）

> 状态：**可直接落地**。所有 HEX、px、alpha、对比度均为实测值（脚本 `.tmp/contrast-subjects.py` → `.tmp/subject-tables.md`，可重跑复核）。
> 范围：`SUBJECTS` 目录的 CSS 绘制主体（`px-grid` / `px-halftone` / `px-scanline` / `px-none`）。
> 不涉及：`px-stars`（canvas 星空，保留不动）、背景照片与遮罩链路、字体体系。

---

## 0. 一页结论

1. **反馈已复现且可代码级证明**：`px-none` / `px-grid` / `px-scanline` 三者对底色的**峰值对比度只有 1.00–1.25:1**，且 `px-grid` 与常驻网格层 `.g-bg-grid` 是**同一图案、同一颜色**，还压在它**下面**（`z-index: -3` vs `-1`）。不是"调深一点"能解决的，而是这一族母题（1px 细线 + 8px 平铺）在 8px 网格常驻的前提下无法互相分离。
2. **替换方案**：删除 `px-grid` / `px-halftone` / `px-scanline` 三套，新增 **5 套重心、形态、填充方式互不相同的纯 CSS 主体**：取景框 / 胶片齿孔 / 像素光圈 / 灰阶色卡 / 工程剖面线。
3. **新增取色阶梯 `--g-subj-faint / -mid / -strong / -accent`**，沿「配色底色 → 正文色」直线二分反解，**不引入新色相**，四套配色 + auto 明/暗共 6 组全部给出实测值（§3）。
4. **规格 §1.6 的 A 级安全区用一条纯 CSS 走廊实现**：中央 1200px 内容列内主体降到 22%，实测透出 ≤1.24:1（目标 ≤1.25:1），走廊外保持 100%；窄屏自动退化为整屏 22%（无需媒体查询）。
5. **已逐项验证**：11×4 预览卡矩阵、P1–P4 全屏舞台、16 张**原生 1:1** 取景窗口、色卡逐像素复核、网格层 5× 放大核对。截图与脚本清单见 §7。

## 1. 问题诊断：为什么"看起来差不多"

### 1.1 实测（表 1，取自 `.tmp/subject-tables.md`）

| 配色 | px-none | px-grid / px-halftone | px-scanline |
|---|---|---|---|
| P1 星夜蓝 | 1.00:1 | **1.17:1** | **1.049:1** |
| P2 米白纸面 | 1.00:1 | **1.25:1** | **1.178:1** |
| P3 墨绿胶片 | 1.00:1 | **1.25:1** | **1.039:1** |
| P4 碳灰霓虹 | 1.00:1 | **1.13:1** | **1.023:1** |
| auto·浅 | 1.00:1 | **1.15:1** | **1.083:1** |
| auto·深 | 1.00:1 | **1.11:1** | **1.011:1** |

三者的最大值差 **1.25:1**，`px-scanline` 甚至低到 **1.01–1.18:1** —— 低于任何屏幕在环境光下的可靠分辨阈值。

### 1.2 机制（三条根因，逐条对应到代码）

| # | 根因 | 代码位置 |
|---|---|---|
| ① | 三套主体都是**同一族母题**：`1px` 线/点 + `8px`（或 `4px`）平铺单元 | `appearance.css:325-330`（px-grid：两个 `linear-gradient` + `background-size: 8px 8px`）、`appearance.css:332-338`（px-halftone：`radial-gradient` 1px 点 + 8px）、`appearance.css:340-347`（px-scanline：`rgb(0 0 0 / .14)` 1px 线 + 4px） |
| ② | 线色**全部取自 `--g-bg-grid`** —— 与常驻网格层同色 | 同上；`--g-bg-grid` 在 §1 四套配色里定义 |
| ③ | 常驻网格层 `.g-bg-grid` 是**同图案同色**，且 z 序更高（-1）**盖在主体（-3）之上** | `appearance.css:429-435`（`.g-bg-grid`，`z-index: -1`，`linear-gradient(var(--g-bg-grid) 1px, transparent 1px)` + `background-size: 8px 8px`）vs `appearance.css:318-323`（`.g-bg-subject`，`z-index: -3`） |

`appearance.css:349-352` 的既有注释已经承认过一次同源冲突（"px-grid 主体本身就是 8px 网格：再叠基础网格层会画两遍同位置线（变粗发黑），所以关掉"）——但这只解决了 `px-grid` 一个特例，`px-halftone` / `px-scanline` 仍然与网格层叠在同一张网上。

原生 1:1 的 5× 放大核对（`.tmp/probe-zoom.png`）证实：常驻网格层是 **8px 节距的真实 1px 格线**，在 P1 下 1.17:1 —— 它本身就是一层"很淡的网格主体"，于是"网格主体 + 网格层"= 双层同图案，与"无主体 + 网格层"几乎无差别。

### 1.3 结论

> 要修的不是"线太淡"，而是**母题本身**。凡是「1px 细线 / 小点 + 8px 平铺 + `--g-bg-grid` 取色」的组合，都会与常驻网格层糊在一起。
> 因此新主体统一遵守两条硬规则：**(a) 平铺单元不再等于 8px（且不与 8px 成整数倍关系）；(b) 结构线取色改用专门阶梯 `--g-subj-strong`（2.8:1 档），不再复用 `--g-bg-grid`。**

## 2. 新主体目录（5 套）

命名与文案沿用既有 `SUBJECTS` 的短句风格（"名字 + 像什么"）。定位一句话：**每套主体先决定"画面的重心在哪"，再决定"用什么母题画"**，五套的重心分别落在：四个角 / 左右两侧 / 右上角 / 底边 / 两个对角。

### 2.1 `px-viewfinder` 取景框

- **名称**：取景框
- **描述（写进 `SUBJECTS.description`）**：「四角取景标尺 + 中心对焦框，像取景器里看世界」
- **视觉形象**：屏幕四个角各有一副 72×6px 的 L 形角标（带 8×8 强调方块），四边贴着屏幕边缘有一条 96px 节距的短刻度尺（高 14px），中央正文列左右各 120px 处各有一个 32×2px 的十字对焦框。整体像相机/取景器的构图辅助层，**只有细线和角点，没有大面积填充**。
- **CSS 实现要点**：
  - `::before`：12 层 `linear-gradient(... 0 0)` 纯色矩形，靠 `background-size` + `background-position` 摆在四个角（4 个强调点 8×8 + 8 条角臂 72×6 / 6×72），上层顺序 = 强调点在最上。
  - `::after`：4 层 `repeating-linear-gradient(90deg/180deg, var(--g-subj-mid) 0 2px, transparent 2px 96px)`（四边刻度尺，`background-size: 100% 14px` / `14px 100%`）+ 4 个十字矩形（`32px 2px` / `2px 32px`，`calc(50% ± 120px) center`）。
  - **不用任何 mask**（除走廊），形态完全由 `background-position` 的角对齐产生。

### 2.2 `px-sprocket` 胶片齿孔

- **名称**：胶片齿孔
- **描述**：「左右片边齿孔 + 片边码刻度，像一条挂在背景里的 35mm 胶片」
- **视觉形象**：屏幕左右两侧各一条 40px 宽的"片基"（`faint` 填充、内缘 2px `strong` 线），片基上每 40px 一个 24×16px 的齿孔——齿孔不是画出来的，而是**用配色底色 `var(--g-bg)` 挖洞**，所以任何配色下都是"透出底色的洞"；顶部另有一条 18px 高的片边码：48px 细刻度 + 240px 粗刻度。
- **CSS 实现要点**：
  - 主体层元素自身：6 层 `linear-gradient`/`repeating-linear-gradient`，其中齿孔用 `repeating-linear-gradient(180deg, var(--g-bg) 0 16px, transparent 16px 40px)`（24px 宽 + 40px 节距，**刻意避开 8px 网格的整数倍**），片基与内缘线用纯色矩形层；`background-position: left/right 8px top` 等。
  - `::before`：顶部片边码（`repeating-linear-gradient(90deg, ... 2px 48px)` + `... 4px 240px`）。
  - 唯一"块面 + 镂空"母题。

### 2.3 `px-aperture` 像素光圈

- **名称**：像素光圈
- **描述**：「右上角六叶光圈与同心曝光环，像镜头正对着你」
- **视觉形象**：右上角外侧（虚拟圆心 86% / -4%）有一组六片光圈叶片——每 60° 一格、格内 3° 硬停叶缝，向外是 22/24px 节距的同心曝光环；光圈只活在右上角 520px 半径内，向中央羽化消失；内圈 138–140px 处有一道 **accent 校色环**（全五套里唯一允许强调色的地方，因为它在 C 级自由区）。
- **CSS 实现要点**：
  - `conic-gradient(from 0deg at 86% -4%, …)` 12 个硬停（`transparent 0 12deg, var(--g-subj-strong) 12deg 15deg, …`）画叶缝；像素风要求"硬停"而不是羽化，这里全部用双停点。
  - `repeating-radial-gradient(circle at 86% -4%, transparent 0 22px, var(--g-subj-faint) 22px 24px)` 画曝光环（节距 24px，同样避开 8px）。
  - `::before` 上的 `mask-image: radial-gradient(circle 520px at 86% -4%, #000 0 60%, transparent 100%)` 把光圈锁在角落（**这是伪元素自己的 mask，与元素上的走廊 mask 相乘叠加**）。
  - `::after`：`radial-gradient(circle at 86% -4%, transparent 0 138px, var(--g-subj-accent) 138px 140px, transparent 140px)` 一道 accent 环。
  - 唯一"曲线 / 径向 / 单角"母题。

### 2.4 `px-colorbar` 灰阶色卡

- **名称**：灰阶色卡
- **描述**：「底边一条五格色卡 + 光楔，像现场校色板」
- **视觉形象**：屏幕底边一条 88px 高的色卡带，顶边 4px `strong` 硬线，带内五格硬分格（`faint` / `mid` / `strong` / `mid` / **`accent`**，分格线在 23% / 46% / 69% / 92%，每格间 2px 分隔线）；色卡上方 96px 处还有一条 8px 高的连续光楔（`bg → strong → bg`），像摄影师的校色参照。
- **CSS 实现要点**：
  - `::before`：`border-top: 4px solid var(--g-subj-strong)` + 4 层 2px 分隔矩形 + 1 层 `linear-gradient(90deg, faint 0 23%, mid 0 46%, strong 0 69%, mid 0 92%, accent 0 100%)`。
  - `::after`：`linear-gradient(90deg, var(--g-bg) 0%, var(--g-subj-strong) 50%, var(--g-bg) 100%)` 的光楔。
  - **走廊羽化需放宽**：`.g-bg-subject-px-colorbar { --g-subj-feather: 200px }` —— 底边是硬边色块，40px 羽化会看出"断裂"。
  - 唯一"实心色块 / 硬分格"母题，也是唯一带彩度的。

### 2.5 `px-hatch` 工程剖面线

- **名称**：工程剖面线
- **描述**：「对角剖面线 + 两个三角分区，像工程图纸的剖面」
- **视觉形象**：45° 等距剖面线，两组叠加（16px 节距的 `mid` 细线 + 64px 节距的 `strong` 粗线）；线只出现在**左上三角和右下三角**（各占对角 24%，向 44% 渐隐），中间形成一条空的对角带，正好是正文列所在的位置。像机械图纸的"剖面区域"标记。
- **CSS 实现要点**：
  - `::before` / `::after` 共用同一组斜线：`repeating-linear-gradient(45deg, var(--g-subj-strong) 0 2px, transparent 2px 64px)` + `... var(--g-subj-mid) 0 2px, transparent 2px 16px`。
  - 两个三角分别用 `mask-image: linear-gradient(135deg, #000 0 24%, transparent 44%)`（::before）与 `linear-gradient(315deg, …)`（::after）。**必须分到两个伪元素**：mask 默认 `add` 合成，两层写在同一元素上会联合覆盖整卡。
  - 需要关闭常驻网格层（45° 斜线叠 8px 正交网会出摩尔纹，且和 §1.3 规则一致）：`html[data-subject='px-hatch'] .g-bg-grid { display: none }`（改写既有 `appearance.css:349-352` 的同一位置规则）。
  - 唯一"斜向 / 反对称"母题。

## 3. 四套配色下如何取色

### 3.1 取色原则

1. **不引入新色相**：`faint / mid / strong` 三档全部落在「该配色底色 → 该配色正文色 `--g-ink`」的直线上，用二分法反解出目标对比度对应的混合比例 ⇒ 新主体天然与配色同源，不会出现"蓝底上的绿线"这种脏色。
2. **四档各司其职**（这是"可读对比度"要求的具体化）：

| 令牌 | 目标对比度（vs 底色） | 用途 | 依据 |
|---|---|---|---|
| `--g-subj-faint` | ≈ 1.25:1 | 可**大面积**铺的填充（片基、曝光环、色卡首格） | 正好等于规格 §1.6 的 A 级安全区上限 |
| `--g-subj-mid` | ≈ 1.8:1 | 中景结构线（刻度尺、剖面线、色卡中格） | 高于纸张纹理、低于硬边 |
| `--g-subj-strong` | ≈ 2.8:1 | 硬边、分格线、叶缝（"看得出结构"的档位） | 贴着规格 §2.6 的 3:1 装饰边界 |
| `--g-subj-accent` | 5.4–10.4:1 | **只允许出现在 C 级自由区**的点缀（角点、校色环、色卡末格） | 复用既有 `accent-2`，不再新增颜色 |

3. **为什么不直接复用既有令牌**：见表 0 —— `surface-3` 只有 1.25–1.80:1（够不到"结构线"），`line-soft` 是 3.28–4.45:1（做细线太抢），`accent-2` 是 6.46–10.38:1（太亮）。既有阶梯缺 1.8 / 2.8 两档，必须补。

## 4. 安全区：把规格 §1.6 变成一条纯 CSS 走廊

### 4.1 实现

```css
:root {
  --g-subj-corridor: 0.22;   /* 走廊内主体透出强度 */
  --g-subj-feather: 40px;    /* 走廊两侧羽化带 */
  --g-subj-mask:
    linear-gradient(90deg,
      #000 0,
      #000 calc(50% - 600px - var(--g-subj-feather)),
      rgb(0 0 0 / var(--g-subj-corridor)) calc(50% - 600px),
      rgb(0 0 0 / var(--g-subj-corridor)) calc(50% + 600px),
      #000 calc(50% + 600px + var(--g-subj-feather)),
      #000 100%);
}
.g-bg-subject-px-viewfinder,
.g-bg-subject-px-sprocket,
.g-bg-subject-px-aperture,
.g-bg-subject-px-colorbar,
.g-bg-subject-px-hatch { -webkit-mask-image: var(--g-subj-mask); mask-image: var(--g-subj-mask); }
```

- 用 **mask 而不是 opacity**：`opacity` 会把边缘构图一起压平；mask 只压中间那一条，A 级让位、C 级满强度，正好对上规格 §1.6 的三级安全区。
- **只挂在 5 个新主体的类上**，不挂 `.g-bg-subject` 通用类 —— `px-stars` 走的是独立 canvas（`SiteBackground.tsx:34-37`），绝不受影响。
- **窄屏自动降级**：390px 视口下 `calc(50% - 600px)` 为负、超出画布，停靠点被 CSS 钳制到 0/100%，于是整屏恒为 `0.22` —— 无需媒体查询就等价于规格 §1.6 的"窄屏 A 级退化为整屏、主体 opacity 0.45"。
- **羽化按主体调整**：`.g-bg-subject-px-colorbar { --g-subj-feather: 200px }`（底边硬边色块的过渡带）。

|---|---|---|---|---|
| P1 | `#24314A` faint | `#16243E` | 1.05:1 ✅ | 14.18:1 |
| P1 | `#3E4A60` mid | `#1C2942` | 1.12:1 ✅ | 13.31:1 |

## 5. 为什么这五套互相之间视觉差异明显

差异不靠"颜色深浅"，而靠**四个正交维度**：重心在哪、什么几何、怎么对称、怎么填充。任意两套至少差 3 个维度：

| 主体 | 视觉重心 | 几何形态 | 对称性 | 填充方式 | 与常驻网格的关系 |
|---|---|---|---|---|---|
| 取景框 | 四个屏幕角 | 正交直线（短臂 + 刻度） | 四重对称 | 细线描边（无填充） | 平铺单元 96px，与 8px 无整数倍关系 |
| 胶片齿孔 | 左右两条竖片基 | 块面 + 镂空（洞透出底色） | 镜面对称 | 实心块 + 挖洞 | 齿孔 24×16 / 40px 节距 |
| 像素光圈 | 右上角（屏外圆心） | 径向曲线（叶缝 + 同心环） | 单角放射（无对称） | 环带 | 节距 24px |
| 灰阶色卡 | 底边横带 | 水平分格（硬边） | 单向（仅左右重复） | 大面积实色块 | 与网格无关（覆盖式） |
| 工程剖面线 | 左上 / 右下两个对角三角 | 45° 斜向 | 反对称 | 等距斜线 + 三角遮罩 | **关闭**网格层（避免摩尔纹） |

再加上与"现状三套"的差异：现状全部是 **1.00–1.25:1 的细线/点**，五套新主体把结构线整体提到 **1.8–2.8:1**，并首次引入 **5.4–10.4:1 的 accent 点缀**。在 214×56 的预览卡里（`.tmp/shot-cards.png`）肉眼即可分辨五行：现状四行几乎一模一样，新五行各不相同。

## 8. 风险与取舍

1. **accent 不能进走廊**：实测走廊内 accent 透出 1.36–1.62:1，超 A 级 1.25:1 上限。方案里已把 accent 的落点限制在 C 级自由区（角点、校色环、色卡两端）。若将来想放宽，需把 `--g-subj-corridor` 从 0.22 降到 0.15 以下，代价是主体在走廊内几乎不可见。
2. **色卡羽化带**：`px-colorbar` 的 `--g-subj-feather: 200px` 意味着 1440px 视口下最右一格处在 1320→1520 的羽化带里（alpha 0.22→0.69），需要 ≥1600px 宽才满强度。若不接受，可把 feather 降到 80px 并接受底带在走廊边界处轻微"断裂"。
3. **`px-hatch` 关闭常驻网格层**：其余四套保留网格层（实测 1.11–1.25:1，等于一层极淡的像素纸纹）。这是"摩尔纹"与"统一纸纹"之间的取舍，选前者。
4. **层叠上下文**：`mask-image` 会创建层叠上下文。主体层是 `z-index: -3` 的 `position: fixed` 元素，本身不与内容竞争，实测无副作用；`px-stars` 是独立 canvas（`SiteBackground.tsx:34-37`），完全不受影响。
5. **兼容性**：`mask-image` 需 `-webkit-` 前缀（附录 A 已双写）。`conic-gradient` / `repeating-radial-gradient` / `calc()` 在 mask 渐变中的支持同 Chromium/Firefox/Safari 现行版本。
6. **性能**：全部是静态 `background-image` 渐变 + mask，零动画、零 canvas、零位图解码；与现有三套主体同级（甚至更省——主体数量不变）。
7. **对比度总量**：新增结构的最高档是 2.8:1（vs 底色），低于 3:1，不参与"可操作边界"判定（规格 §2.6 要求 `--g-line-hi` ≥3:1 用于可操作边界，本方案未触碰该令牌）；正文/控件对比度不受影响（正文最坏 8.09:1）。
